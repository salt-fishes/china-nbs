# 限流、缓存与请求预算

上游是试运行期的政府网站，默认策略是“少发、慢发、可解释”。

## 1. 默认行为

| 项 | 默认值 |
|---|---|
| 并发 | 串行，同一时间只发 1 个请求 |
| 请求间隔 | ≥ 2000ms，另加 0–250ms jitter |
| 单请求超时 | 20000ms |
| 整次查询超时 | 45000ms |
| 重试 | 5xx / 429 / 网络错误重试 1 次，等待 5s + jitter |
| 403 | 不重试，返回 `UPSTREAM_BLOCKED` |
| 缓存 | 进程内 TTL + LRU，最多 200 条 |
| 负缓存 | `NOT_FOUND` 结果缓存 5 分钟 |
| 熔断 | 连续 5 次可重试失败后打开，冷却 30 秒 |

## 2. 缓存 TTL

| 内容 | TTL |
|---|---|
| 关键词搜索 | 10 分钟 |
| 时间序列 | 30 分钟 |
| 分类树 | 24 小时 |
| 指标列表 | 24 小时 |
| 省份列表 | 7 天 |

缓存键包含端点、参数和请求体；相同查询会走 in-flight 去重。

## 3. 实际请求预算

| 动作 | 解析 | 数据 | 典型请求数 |
|---|---|---|---|
| `search`（命中 curated） | 0 | 1 | 1 |
| `search`（走搜索） | 1 搜索 | 1 | 2 |
| `search`（走分类树） | 1–6 树/指标 | 1 | 2–7 |
| `series`（全国/分省单分片） | 0–1 | 1 | 1–2 |
| `series`（全国/分省 CPI 4 个分片） | 0–1 | 4 | 4–5 |
| `series`（主要城市年度） | 0–2 树/指标 | 1 | 1–3 |
| `compare`（3 省，年度/季度） | 0–1 | 3 | 3–4 |
| `compare`（3 省，CPI 月度） | 0–1 | 3（每个省 1 个分片） | 3–4 |

说明：

- `compare` 实测 `das` 传多个地区只返回第一个，所以按地区逐个请求。
- 分省季度 GDP / 月度 CPI 已内置 curated，通常只需数据请求；其他分省指标仍要走分类树。
- 主要城市年度首次查询需要分类树 + 指标列表，之后走 24 小时缓存；广州 GDP 已 curated。
- 2 秒间隔下，4 个分片至少约 8 秒；`totalTimeoutMs` 默认 45 秒，足够覆盖常见长序列。
- 分类树和指标列表有 24 小时缓存；同一进程内重复查询不会反复打上游。
- `npm run eval:live` 会跑 168 条用例；curated 用例不请求上游，只有长尾用例走 search/tree。

## 4. 延迟预期

| 场景 | 预期 |
|---|---|
| 缓存命中 | < 10ms |
| 单请求实时 | 约 0.2–1.5s |
| 2 请求（搜索 + 数据） | 约 2–4s |
| 4 分片月度长序列 | 约 8–12s |
| 403 / 超时 | 立即或按超时返回，不无限重试 |

不要承诺固定 P95；上游试运行期抖动较大，应在调用方设置自己的超时和降级策略。

## 5. 对 qbot 的建议

- 单轮最多 1 次 `stats` 调用；如果返回 `AMBIGUOUS`，让用户选，不要自动猜。
- 带 `indicatorId` 的后续查询可以复用候选，避免重复搜索。
- `UPSTREAM_BLOCKED` / `TIMEOUT` 时明确说“数据库暂时没取到”，不要编造数值；必要时回退 `web` 查新闻/解读，并注明来源不同。
- 群聊并发高时，在 qbot 层加每群/全局频率限制；库本身只保证进程内串行。
